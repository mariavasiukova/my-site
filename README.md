## Ответы на вопросы

### Чем отличается CI от CD?

**CI (Continuous Integration)** — непрерывная интеграция: каждый push в репозиторий автоматически собирается и тестируется. Цель — как можно раньше обнаружить ошибки.

**CD (Continuous Delivery/Deployment)** — непрерывная доставка/развёртывание: после успешных тестов код автоматически попадает в продакшен (Deployment) или готов к развёртыванию по команде (Delivery).

Кратко: CI — про проверку кода, CD — про доставку кода до пользователя.

### Что произойдёт, если тесты завершатся ошибкой на этапе CI?

Пайплайн остановится на шаге `npm test`, последующие шаги (build, upload-artifact) не выполнятся. Задача `deploy` не запустится, так как она зависит от `ci` через `needs: ci`. Неработоспособный код не попадёт в продакшен.

### Для чего используется директива `needs: ci` в задаче развёртывания?

Директива `needs: ci` создаёт зависимость: задача `deploy` запускается только после успешного завершения задачи `ci`. Если `ci` упадёт, `deploy` не выполнится. Это гарантирует, что в продакшен попадёт только проверенный код.

### Что такое артефакт и для чего он передаётся между задачами?

**Артефакт** — это файл или набор файлов, созданных в ходе выполнения workflow (в нашем случае — папка `dist/` с собранным сайтом).

Артефакт передаётся между задачами (`ci` → `deploy`), потому что задачи выполняются на разных runner'ах и не имеют общего файлового пространства. Через `upload-artifact` в задаче `ci` и `download-artifact` в задаче `deploy` мы передаём собранный сайт для публикации.
